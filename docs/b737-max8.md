# Boeing 737 MAX 8 profile (MSFS 2024 default Boeing 737 MAX 8)

**Status: generated (AIR-1), not yet sim-tested; 7 pages, 107 keys.** The profile `MSFS2024 737 MAX 8` is
built by the generator, but nothing on it has been tried in the app or the sim yet. Every name below is
recorded as "Unverified" in [aircraft-mappings.md](aircraft-mappings.md) ("Boeing 737 MAX 8 (MSFS 2024
default, AIR-1, input event list 737MAX8)") until the checks in
[tests/manual-checklist.md](../tests/manual-checklist.md), section "Boeing 737 MAX 8 profile (AIR-1)", pass.

Goal: a first useful airliner profile for the Boeing 737 MAX 8 that comes with MSFS 2024 (the default
aircraft, no add-on or mod). Its main page has its own grid round the mode control panel (MCP), with the
folder keys TRIM, VIEWS and SIM RATE where the other profiles have them: 7 pages, 107 keys. Every readout and
lit key shows the sim's own value; a key whose state has no source has no light (a fixed image). No key
assumes its press worked.

**Built from the 737's input event list and three captures.** The cockpit's switches, knobs and buttons are
input events (B-vars) of the list `docs/reference/InputEvents-737MAX8.txt`. Three captures recorded what
each variable did while the user worked the cockpit controls with the mouse, on the ground and in a short
flight: they give the value maps of the switches and the lights of the MCP mode keys. A capture is not a test
of a key: every key is Unverified until the hand test.

The data file is `tools/profilegen/b737max8.json`; the key tables below are the reference, and
`python tools/profilegen/check.py tools/profilegen/b737max8.json` compares the profile with them key by
key. The sim rate page calls the shared script `XL24-SIMRATE.lua`; this profile's own script `XL24-B737.lua`
(in the package's `Scripts` folder) runs hold to repeat ("Hold to repeat").

Nothing in this profile uses keyboard bindings, vJoy or anything tied to a controller: the keys write the
737's input events, send standard SimConnect events and Lua functions, write one SimVar (the camera state),
and read input events, L-vars and SimVars, so they work the same with the Xbox
Elite controller and the T.16000M + TWCS. No key uses an H-event, so the profile does not need the
MobiFlight WASM module.

## What the 737's files and the captures show

- **Input event list** [IE]: PilotsDeck wrote `InputEvents.txt` when a 737 MAX 8 flight loaded with it
  running (2026-11-27); the copy in `docs/reference/` is the file as it was. Every `B:` name on these pages
  is a line of it.
- **L-var list** [LV]: the sim's L-var list that PilotsDeck wrote in the same session. It holds the L-vars of
  every aircraft loaded in that session, so a name in it is only a candidate until a capture shows the 737
  uses it.
- **Aircraft string** [LOG]: the plugin log names the 737's files under
  `...\asobo_b737max\presets\asobo\b737max8_passengers\...` ("Profile Manager mapping").
- **Captures 1 and 2** [B1, S1, S2] (2026-11-27, on the ground): the switches and knobs hold their values in
  their B-vars and the SimVars follow within 0.3 s; the MCP buttons only pulse their B-vars (0, 1, 0 in 0.1 to
  0.3 s), so a button's B-var has no state to light a key.
- **Capture 3** [V, SC, SD] (2026-11-28, a short flight: engine start by hand, takeoff, climb with the
  autopilot): it gives the lights of SPEED, VNAV, LVL CHG, HDG SEL, APP and V/S (the 737's own L-vars light at
  the press), CMD A (`AUTOPILOT MASTER`) and ALT HLD (`AUTOPILOT ALTITUDE LOCK`); A/T 1 = ARM in flight; the
  start switch and the start lever (below); the gear, flap, autobrake, ignition selector and speed brake
  values; the V/S step (100 fpm per wheel click) and the V/S readout. The EFIS, the bank ring, C/O, the cabin
  signs and the lights after landing were not in it: their keys take the fallbacks of "Keys without a light
  or on a fallback".
- **Start switch and start lever:** the start switch is `B:engine_ignition_1` / `_2` (0 = GRD: the starter
  SimVar followed within 0.1 s each time), the start lever `B:engine_starter_1` / `_2` (1 = IDLE, 0 =
  CUTOFF). The lever's link to the engine is inferred from the order of events in capture 3 (the levers went
  to 0 and engine 1 stopped 2.6 s later; by hand back to 1 and the engine ran later with its starter on), not
  from a pair within 0.3 s.

## Where the pages sit

The main page has no back key. Every child page has its back key at 1,1; one folder level
([navigation.md](navigation.md), "MSFS2024 737 MAX 8 pages"). Every child page opens from main and its back
key returns to main.

| Opened by | Page | Level | Holds |
|---|---|---|---|
| main 1,7 `TRIM` | trim | 1 | the CJ4's trim page: elevator, aileron and rudder trim keys and gauges; the six trim keys hold to repeat |
| main 1,8 `VIEWS` | views | 1 | the CJ4's views page as it is |
| main 2,7 `MCP` | mcp | 1 | the rest of the MCP (F/D, CMD B, CWS, the disengage bar, A/T DISC, C/O, SPD INTV, TOGA, BANK, the CRS and V/S columns) and the Captain's EFIS |
| main 3,7 `SIM RATE` | simrate | 1 | the CJ4's sim rate page as it is (`XL24-SIMRATE.lua`) |
| main 3,8 `PED` | ped | 1 | FLAPS and GEAR again, SPD BRK, A/BRK, PARK, the guarded START and CUTOFF keys and IGN |
| main 4,7 `LIGHTS` | lights | 1 | the exterior lights and the two cabin sign readouts |

Main 2,8 and 4,8 show nothing and do nothing: they are kept for the OVHD and MORE folder keys of a later set
("Not on these pages, and why").

## What the keys do

- **Main, mode keys:** N1, SPEED, VNAV, LVL CHG, CMD A, HDG SEL, LNAV, VOR LOC, APP, ALT HLD and V/S press the
  MCP button: the key writes 1 to the button's input event and 0 again 100 ms later (Reset Switch), as the
  cockpit button pulses it. SPEED, VNAV, LVL CHG, HDG SEL, APP and V/S light from the 737's own mode L-var,
  CMD A from the autopilot master SimVar (lit for either autopilot), ALT HLD from the altitude hold SimVar.
  N1, LNAV and VOR LOC have no light: no variable that capture 3 watched changed at their press.
- **Main, A/T:** the autothrottle arm switch, written and read on its input event (1 = ARM).
- **Main, the SPD, HDG and ALT columns:** SPD+/-, HDG+/- and ALT+/- step the MCP's speed, heading and altitude
  and repeat while held; SPD, HDG and ALT show the knobs' input events and do nothing on a press.
- **Main, FLAPS:** shows the flap handle position as a number (0 = up, one step per detent): a press moves it
  one step out, a long press (half a second or more) one step in, by the standard events.
- **Main, GEAR:** the gear lever, written and read on its input event (1 = DOWN, 0 = UP). A press moves the
  lever: never press it on the ground expecting nothing.
- **Main, A/P DISC:** presses the yoke's autopilot disconnect button (no light: CMD A shows the result).
- **MCP:** F/D L and F/D R switch the flight directors (1 = ON). CMD B, CWS A, CWS B, A/T DISC, C/O, SPD INTV
  and TOGA press their buttons, with no light. DISENGAGE shows the disengage bar's raw value and does nothing
  on a press. CRS+/-, V/S+/- and BARO+/- step the course, the vertical speed target and the altimeter setting
  and repeat while held; CRS, V/S and BARO show them. BANK shows the bank ring's raw position (0 to 4) and
  steps it on a press. MODE and RANGE show the EFIS selectors' raw positions; CTR, TFC, TERR, WXR, STD and
  MINS RST press their EFIS buttons, with no light; MINS+ and MINS- step the minimums once per press, MINS
  shows the raw value.
- **Lights:** POS steps the position light switch through STEADY, OFF and STRB, the others switch their light
  and light from the switch's own input event. SEAT BELT and NO SMOKE show the sign switches' raw values.
- **Ped:** SPD BRK shows the speed brake lever's value (0 = down) and does nothing on a press. A/BRK steps the
  autobrake selector and shows its position. PARK sets and releases the parking brake (1 = SET). IGN steps the
  ignition selector and shows its raw position. START 1 / 2 and CUTOFF 1 / 2 act on a long press only.
- **Copied pages:** trim, views and sim rate work as on the CJ4 (their docs above); they use standard events,
  SimVars and the shared Lua script, nothing 737-specific.

## Hold to repeat

The step keys repeat while held, by the route of the CJ4 profile ([cj4.md](cj4.md), "Hold to repeat"):
each step key is a Simple Button with **Hold Switch** on and the command type Lua Function; key down runs
`lua:XL24-B737:HOLD(n)`, key up `lua:XL24-B737:RELEASE(n)` (README 2.1.2). n is the key's code (table
below). The speed profiles, the step caps, the 20 s limit and the rules for a short press, a hold and a
lost key up are the CJ4 script's ([cj4.md](cj4.md), "Hold to repeat"); the CJ4's hold test in the sim has
not been run yet, so this is not proven there either.

**The 737's knobs are written, not stepped by an event.** The captures show that the MCP knobs are input
events that hold the selected value (1 kt, 1 degree and 100 ft per click), and that the ALT knob does not
move the SimVar the standard altitude event sets (S1). So the codes 1 to 10 write a B-var value: at key down
the script reads the base value (`SimVar` / `SimRead`, README 3.5.1), then each step adds the key's step to
the value it wrote last, keeps it in the key's limits and writes it with `SimCommand("B:<name>:<value>")`
(README 3.5.1 with the B-var form of README 2.1.1). Whether `SimRead` reads a B-var and whether the value
lands as written is **not in the README**: a hand test. The codes 11, 12 and 15 to 20 send K-events, as the
CJ4 script does.

- **V/S reads its base from the SimVar** `AUTOPILOT VERTICAL HOLD VAR`, the value the V/S readout shows: the
  V/S wheel's B-var takes the target when V/S engages and follows each click, but keeps its last value when
  the mode ends (it kept 4300 from V 00:52:12.1 while the target went to 0, SC 00:53:10.1).
- The clamps 100 to 399 kt and 0 to 50000 ft are working values: no source gives the 737's MCP limits.
- The script writes only the B-vars of its key table and sends only its events; it does not check which
  aircraft is loaded.

## Guarded keys

**START 1, START 2, CUTOFF 1 and CUTOFF 2 act on a long press only** (half a second or more): a short press
writes nothing. The long press toggles the input event between the key's two values: it writes the Off value,
or the On value when the key reads Off (PD-LONG). START: On `0` (GRD), Off `1`; CUTOFF: On `1` (IDLE), Off
`0` (CUTOFF). A START key that reads 2 (the switch's value with the engines running, its label not shown)
writes 1 on a long press, and shows the Special State image while it reads 2.

- Whether PilotsDeck runs the long press command of a key whose short press command is none is a hand test:
  no other profile in the repo has such a key.
- Plain, as their cockpit controls: GEAR, PARK, the light switches, A/T, F/D and the selectors. GEAR moves the
  gear lever at a press: press it only on purpose.
- The disengage bar is a readout (its down value is not known), so no key moves it.

## Keys without a light or on a fallback

The keys whose state or values the captures did not settle, and the items the hand test checks on the
settled keys. Each is a step of the checklist section.

- **No light, press kept:** main N1, LNAV, VOR LOC, A/P DISC; mcp CMD B, CWS A, CWS B, A/T DISC, C/O, SPD
  INTV, TOGA, CTR, TFC, TERR, WXR, STD, MINS RST. Check that each press does what the cockpit button does
  (A/P DISC: if not, the lead `K:AP_MASTER` [AM 20] needs a 737 test).
- **Readout only, no command:** main SPD (what it shows in Mach after C/O is not known), main ALT (no ALT
  INTV press); mcp DISENGAGE, MODE, RANGE; lights SEAT BELT, NO SMOKE. Check that each shows a number that
  changes with the cockpit control, and record the number per position.
- **Raw positions, no labels:** mcp BANK (0 to 4), ped IGN (0 to 2), SPD BRK (0 to 80); record the cockpit's
  label per number.
- **Working value kept:** lights LOGO, LAND R, RWY L, RWY R (On `0` / Off `1`, the form of the other light
  switches; not switched in any capture). Check that the key's light matches the cockpit switch, both ways.
- **Fallback writes:** mcp BARO+/- (`K:KOHLSMAN_INC` / `_DEC`; if they do not move the 737's baro, single
  steps on `B:efis_baro_1`), MINS+/- (single steps `$1` / `$-1`; the knob's step is not known), the MINS
  readout (the raw value of `B:efis_mins_1`, the B-var the two MINS keys write: a readout of a sourced sim
  state instead of an empty key).
- **Inferred from capture 3:** the A/BRK labels (`0=RTO:1=OFF:2=1:3=2:4=3:5=MAX`; 0 is an end position and
  the six labels in knob order fit, but no source names them) and the CUTOFF lever's link to its engine (by
  the order of events, not by a pair within 0.3 s). Check both by hand: the A/BRK label per cockpit position,
  and that CUTOFF 1 and 2 stop and start their own engine.
- **Hand-test items on settled keys:** the B-var write route of the codes 1 to 10 ("Hold to repeat"); LVL
  CHG's light against `AUTOPILOT FLIGHT LEVEL CHANGE` (the two disagreed for 4.5 s in capture 3); the off of
  HDG SEL and APP (only the on was shown); CMD A lit for either autopilot; GEAR down (shown by the start value
  only); FLAPS by the K-events (fallback `B:handling_flaps`); the START and CUTOFF guards and values, engine 2
  included.

## What the keys show when the 737 isn't there

- No sim, or no flight: PilotsDeck's own idle and waiting images, as on the other profiles.
- Another aircraft: the keys that read the 737's input events and L-vars show whatever that aircraft has
  under those names (most likely nothing, or 0); the SimVar readouts show its own values.
- **Keys act on any aircraft that has their names:** the B-var writes go to that aircraft's input events of
  the same name, and FLAPS, BARO+/-, the trim keys, the views and the sim rate keys are standard events and
  SimVar writes. Do not press them in another aircraft. The step keys act the same way and repeat while
  held (the script does not check the aircraft).
- If the 737 ignores a write or an event, the key's read stays where it was and its image does not change:
  the hand test records it.

## How to test

Run [tests/manual-checklist.md](../tests/manual-checklist.md), section "Boeing 737 MAX 8 profile (AIR-1)".
As on the other profiles, check both directions: press a key and watch the cockpit, then **work the control
in the cockpit with the mouse and check that the key follows without a key being pressed.** Hold each step
key for 1, 3 and 10 s and check that the repeat stops at once on release and never runs on. Record which
keys do nothing, the labels per number of the raw readouts, the step per press of BARO+/- and MINS+/-, and
every value that does not match the cockpit.

## When it passes

1. Any change found in the test goes into `tools/profilegen/b737max8.json` and this doc; then the profile is
   regenerated (not exported from the app) and imported again.
2. Fill in the "Verified" column of the rows in aircraft-mappings.md ("Boeing 737 MAX 8 (MSFS 2024 default,
   AIR-1, input event list 737MAX8)") with the date and sim version, for each function that passed; mark a
   row "does not work" where a key failed.
