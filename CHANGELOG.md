- check.py now checks that every `lua:<Script>:<Function>(...)` key names a script file in `pilotsdeck/MSFS2024-XL/_Package/Scripts/` (name case aside, as PilotsDeck finds it) and a function defined at top level in it (P2-6R3; the 1X key's `SET` and the COM1 pad's `DIGIT`, `BACK`, `CLEAR`, `ENTER`, `ENTER_SWAP`).
- check.py now fails a `lua:` key with another ':' after `lua:<Script>:` (PilotsDeck splits the address at every ':' and keeps only the third part, so for `SET("1:2")` it keeps `SET("1`, which fails its own address check: no Lua function runs), and its `lua:` messages name the real script file (or, if it is missing, the lowercase `<script>.lua` PilotsDeck looks for) instead of the call's spelling plus ".lua" (P2-6R3a).
- check.py now fails a `lua:` key whose address PilotsDeck's own address check (rxLuaFunc) rejects, so no Lua function runs: for example `SET()` (empty parentheses), a one-character script or function name such as `S(1)`, or `.LUA` in place of `.lua` (P2-6R3c).
