The main page in short:

| Row | Keys |
|---|---|
| 1 | BAT, RPM, FUEL PMP, PARK, GEAR (gear type), FLAPS (readout; press down, long press up), TRIM folder, VIEWS folder |
| 2 | AP, HDG, ALT, VS, NAV, APR, FLC, FD: mode keys that read the mode state |
| 3 | COM1 (active and standby, press swaps), XPDR (code readout), ATC, MAP, CDI (GPS/VLOC), BARO, SIM RATE folder, CHECKLIST folder |
| 4 | NAV LT, BCN, STRB, LDG, TAXI, PITOT (input-event switches that read the switch), reserved, MORE folder |

Key kinds in use: Dynamic Buttons that read state (switches, AP modes), Display Value readouts, two COM
Radio keys (main 3,1 and the COM pad's COM1), Simple Buttons for commands with no state (ATC, MAP, bezel
keys, trim, SLOWER, FASTER), and Stream Deck folder and back keys. Thirteen keys send a Lua Function
command: `1X` (a Dynamic Button) and the COM pad's digit, CLR and ENT keys (Simple Buttons). No key uses the
Display Gauge, Korry Button or Composite Action, and no key has a dial (the XL has none).

Package format, as the PilotsDeck examples show it (and the
[PilotsDeck README](https://github.com/Fragtality/PilotsDeck/blob/master/README.md) describes):

- A package is a zip archive, `.ppp` or `.zip`. At its root: `package.json`, `Profiles/` (one or more
  `.streamDeckProfile` files), `Scripts/` with `global/` and `image/` subfolders, and `Images/`.
- `package.json` fields seen in real packages: `packageformat`, `title`, `versionpackage`, `aircraft`,
  `author`, `url`, `notes`, `versionplugin` (the lowest plugin version it needs) and `removefiles` (old
  script files the install deletes).
- The Profile Manager installs it: it shows the notes, can remove same-named old profiles, copies images
  and scripts into the plugin folder, then offers each profile for import into the Stream Deck app.
- Automatic switching: in the Profile Manager a profile is enabled for switching and given search strings
  matched against the aircraft string the sim reports, or made a simulator's default; a profile can also be
  the one loaded after the sim closes.
- The Generic G1000 example is a bare profile (no `package.json`), imported in the Stream Deck app. The
  work folder example `PackageTest1` holds only `_Package/package.json`, the same layout as this repo's work
  folder.

### C.3 What the community has that this repo lacks (summary)

- Value controls: selected heading, altitude, VS, speed and course with readouts (every G1000 product).
- More radios: NAV1, NAV2, COM2, transponder code entry and IDENT.
- More systems: electrical, fuel, engine readouts, circuit breakers, interior lighting.
- Gauges and richer images (Display Gauge, Korry buttons, multi-state images).
- Airliner coverage: FCU, EFIS, overhead, pedestal, MCDU keyboard, radio and audio panels.
- Pages by flight phase, ground-service menus, camera pages with many views.
- An installable package with automatic profile switching by aircraft.

### E.1 Lane C: C172 G1000 (runs first)

**P3-1 AUTOPILOT page** (running; not re-planned)

- Scope: a new folder under MORE with state-aware GFC 700 mode keys (AP, FD, YD, HDG, NAV, APR, BC, ALT, VS,
  FLC, and VNV and LVL where the aircraft has them) and HDG bug, ALT select, VS, FLC speed and CRS1, each

- Note: the selected heading readout can start from `(A:AUTOPILOT HEADING LOCK DIR, Degrees)`, already listed

- Files (as ruled): M `tools/profilegen/c172-g1000.json`, M the G1000 profile, C `docs/phase3-autopilot.md`,
  the five shared docs; a Lua script only if a readout or step needs one. Shared tool code: only under a
  lock, if the build needs it.

**P3-2 RADIOS: transponder and NAV radios** (queued; not re-planned)

- Scope: transponder code pad, IDENT and mode; NAV1 and NAV2 tuning and swap; COM2.
- Note: the code pad can follow the COM pad's pattern (a second-level page and a standard Lua script), and the
  XPDR readout reads `(A:TRANSPONDER CODE:1, Bco16)` (already listed, SDK radio variables). Proposed split if
  it passes about 40 keys: P3-2 = transponder pad page, P3-2b = NAV1/NAV2/COM2 radio page, in that order
  (the pad reuses a proven pattern; the radio page needs the most new names).
- Files: M `tools/profilegen/c172-g1000.json`, M the G1000 profile, C a page doc per page (named in the
  brief), maybe C a Lua script under `pilotsdeck/MSFS2024-XL/_Package/Scripts/` for the code pad.
- Size: M (one or two pages). Depends on: P3-1 (same data file). Shared tool code: none expected.

- P5-1 can run beside page units that do not change the same tool files.
- P5-4 changes lane C and lane A data files and profiles, so it runs between their units, never beside one.

## F. Open questions for the user

1. **Which C172 pages after radios and systems?** Options: engine and fuel readouts (P3-5), checklist
   (P3-8), more camera views (P3-7). Recommendation: engine and fuel readouts first, since they are used in
   flight and need no content choice.
2. **How far should the A32NX go?** Options: FCU, EFIS and overhead only; or also the MCDU keyboard (about 70
   keys). Recommendation: build the MCDU keyboard last in lane A; the sim's own MCDU stays usable.
3. **What should the checklist page show?** Options: read-only state lamps for start-up and before take-off;
   a text checklist with tick keys; nothing. Recommendation: read-only state lamps (no automation, matches the
   plan).
4. **A safe default profile for other aircraft?** Options: none; mappings only; a small universal profile.
   Recommendation: mappings now with P5-PKG, the universal profile after the A32NX main page.
5. **Committed images?** Options: keep the local pack build only; draw a small own set; ask the pack's author
   for permission. Recommendation: a small own set for state colours, keeping the pack as the local option.
6. **Benchmark for "parity"?** Options: the paid C172 G1000 profile's areas (autopilot, radios, lights,
   PFD/MFD, breakers); the free XL profiles' areas. Recommendation: the paid profile's areas except circuit
   breakers.
7. **Ground services and other devices?** Options: a GSX menu folder (paid add-on); Stream Deck + or 15-key
   versions. Recommendation: neither for now (XL only, no paid dependency).
